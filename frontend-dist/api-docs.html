API 文档

本页说明本站的上传、鉴权、文件访问、列表、删除和过期清理接口。请求地址使用你的图床域名，以下示例用 https://img.example.com 代替。

新上传默认保存 24 小时，临时文件最多 7 天。到期前可重复访问，没有一次性模式。永久保存需显式申请并具备管理员权限；默认存储渠道仍为 Telegram。

快速开始 Token 与权限 上传参数 访问文件 会话与保存策略 渠道、列表与删除 过期清理 分块与直传 旧接口兼容

快速开始

使用带 upload 权限的 API Token。把示例域名换成你的域名，并设置 IMGBED_UPLOAD_TOKEN。上传采用 multipart/form-data，文件字段名为 file，每个请求上传一个文件。使用 curl 的 -F 时无需手动设置 Content-Type。

# 默认保存 24 小时；returnFormat=full 返回完整链接
curl --fail-with-body \
  -H "Authorization: Bearer $IMGBED_UPLOAD_TOKEN" \
  -F "file=@image.jpg" \
  'https://img.example.com/upload?returnFormat=full'

# 保存 7 天；expiresIn 的单位为秒
curl --fail-with-body \
  -H "Authorization: Bearer $IMGBED_UPLOAD_TOKEN" \
  -F "file=@image.jpg" \
  'https://img.example.com/upload?returnFormat=full&expiresIn=604800'

# 永久保存；Token 必须同时有 upload 和 manage 权限
curl --fail-with-body \
  -H "Authorization: Bearer $IMGBED_ADMIN_TOKEN" \
  -F "file=@image.jpg" \
  'https://img.example.com/upload?returnFormat=full&permanent=true'

上传成功返回 HTTP 200，响应仍是数组：

[
  {
    "src": "https://img.example.com/file/example.jpg",
    "expiresAt": 1791421200000
  }
]

将 src 用作文件地址。通过 Buffer 排期时，保存时间应覆盖实际发布时间；超过 24 小时的排期应指定更长时间，最多 7 天，或由管理员申请永久保存。

Token 与权限

在管理端的安全设置 → API Token 管理中新建 Token。自动化调用推荐请求头 Authorization: Bearer <TOKEN>；原有直接填写 Token 的 Authorization 格式也保留。

用途Token 权限
临时上传（默认 24 小时，最多 7 天）upload
永久上传同时具有 upload 和 manage
管理文件列表list
删除文件delete
过期清理及其他管理操作manage

浏览器可使用已有用户或管理员登录会话上传。旧上传调用的 authCode 查询参数也保留；未设置用户认证时可匿名临时上传。这些身份均不会自动获得永久保存能力。

使用管理员会话申请永久，必须先配置完整的管理员用户名和密码，经 管理员登录页登录，上传请求携带有效的 admin_session Cookie。仅关闭管理端认证不会获得永久保存权限。管理员上传不传保存参数时也仍为 24 小时。

Token 自己的 expiresAt 是 ISO 日期，控制凭据有效期；上传响应的 expiresAt 是文件的到期时间。两者独立，没有新增每个 Token 的文件保存时长设置。

POST /upload

请求体是含 file 的表单。以下参数放在 URL 查询字符串中，保存时间不放在表单字段或 Token 配置中。

参数默认值说明
expiresIn86400整数秒数，范围 1–604800，有效期从上传完成时开始。
permanentfalsetrue 申请永久保存；需要管理员会话，或同时具有 upload、manage 权限的 Token。
returnFormatdefaultdefault 返回相对路径；full 返回本站完整链接。
uploadChanneltelegramtelegram、cfr2、s3、discord、huggingface、webdav。需在站点配置对应渠道。
channelName不指定选择该类型下已配置的具体渠道名称，查询渠道接口获取可用名称。
uploadFolder根目录文件目录，例如 twitter/media。查询参数需 URL 编码。
uploadNameTypedefault原有命名方式：default、index、origin、short。
autoRetrytrue失败时自动切换可用渠道；传 false 关闭。需要固定存储渠道时可关闭。
serverCompress开启Telegram 上传中传 false 使用文档方式发送，避免 Telegram 的图片压缩。

permanent=true 与 expiresIn 互斥；重复保存参数、非法布尔值、非整数秒数、超出范围均返回 400。普通身份申请永久返回 403。

响应字段

字段说明
src文件地址；默认形如 /file/example.jpg。
expiresAtUnix 毫秒时间戳；永久文件为 null。
publicUrl可选字段，仅配置公开链接前缀时返回。前缀的有效期行为取决于其指向的服务。

常见错误

HTTP 状态含义
400保存参数非法、分块参数不匹配等请求错误。
401需要上传认证且没有可用凭据；检查 Token 有效期、upload 权限或登录会话。
403没有永久保存权限，或上传 IP 被封禁。
500 / 503存储上传失败，或配置、数据库暂不可用。

保存参数错误的响应是 JSON 对象，例如 {"error":"expiresIn must be an integer between 1 and 604800 seconds"}。其他旧错误可能返回纯文本；先判断 HTTP 状态，再处理响应体。

GET /file/{文件ID}

使用上传返回的 src 访问文件，支持 HEAD 和 Range 请求，仍受本站原有文件访问策略约束。临时文件使用 Cache-Control: no-store；到期后 GET、HEAD、Range 和图片处理请求返回 404。

curl -I 'https://img.example.com/file/example.jpg'

到期链接立即失效，物理删除可能滞后。存储渠道自身的公开直链、第三方下载的副本不受本站链接有效期控制。

Worker 和 Docker 支持临时文件的图片处理。Pages 仅使用 /cdn-cgi/image 时，临时文件图片转换返回 400，可用 fallback=original 返回原图。

GET /api/auth/sessionCheck

返回浏览器会话状态及保存策略。可以携带 API Token 查询永久保存能力：

curl -H "Authorization: Bearer $IMGBED_UPLOAD_TOKEN" \
  'https://img.example.com/api/auth/sessionCheck'

没有浏览器会话时，示例响应为：

{
  "valid": false,
  "adminRequired": true,
  "userRequired": true,
  "canStorePermanently": false,
  "defaultRetentionSeconds": 86400,
  "maxRetentionSeconds": 604800
}

adminRequired、userRequired 取决于站点认证配置；有效会话还包含 authType（admin 或 user）。valid 描述浏览器会话，不代表 Token 是否有效；canStorePermanently 描述当前凭据是否可申请永久。该接口不会把 Token 转换成登录会话。

渠道、列表与删除

GET /api/channels

查询可用渠道名称和类型；使用可用的 API Token 或本站登录凭据。返回按 telegram、cfr2 等键分组的数组，例如 {"telegram":[{"name":"Telegram_env","type":"TelegramNew"}],"cfr2":[]}，实际还包含其他渠道类型。

curl -H "Authorization: Bearer $IMGBED_UPLOAD_TOKEN" \
  'https://img.example.com/api/channels'

GET /api/manage/list

Token 需要 list 权限，或使用管理员会话。常用查询参数：start（默认 0）、count（默认 50）、dir、search、recursive=true。响应包含 files、directories、totalCount 和 returnedCount 等字段。列表过滤已到期文件。

curl -H "Authorization: Bearer $IMGBED_LIST_TOKEN" \
  'https://img.example.com/api/manage/list?start=0&count=20&dir=twitter'

DELETE /api/manage/delete/{文件ID}

Token 需要 delete 权限，或使用管理员会话。文件 ID 使用列表中的 name，保留目录层级并对各路径段进行 URL 编码；不要填入完整文件 URL。原有 GET 删除调用也保留。

curl --fail-with-body -X DELETE \
  -H "Authorization: Bearer $IMGBED_DELETE_TOKEN" \
  'https://img.example.com/api/manage/delete/example.jpg'

成功响应：{"success":true,"fileId":"example.jpg"}。

POST /api/manage/cleanupExpired

需要 manage 权限的 Token，或已配置管理员凭据且有效的管理员会话。无需请求体；每次最多扫描 5 条记录并删除已到期文件，自动保存扫描进度。

curl --fail-with-body -X POST \
  -H "Authorization: Bearer $IMGBED_ADMIN_TOKEN" \
  'https://img.example.com/api/manage/cleanupExpired'
{
  "scanned": 5,
  "deleted": 2,
  "failed": 0,
  "hasMore": true
}

scanned 是本轮扫描记录数，deleted 是成功删除数，failed 是删除失败数；hasMore 表示本次扫描尚未遍历完数据库，可继续调用。删除失败时保留记录供后续扫描重试，不代表请求整体失败。

Worker 和 Docker 每分钟自动清理。Pages 需外部定时任务调用此接口；到期访问也会触发该文件清理。链接是否失效独立于后台清理进度。

Telegram Bot API 仅能删除发送后不足 48 小时的消息。保存 2–7 天的媒体需配合聊天原生自动删除；超过 48 小时，本站链接仍失效并清理本地引用，远端媒体依赖聊天自动删除。临时与永久文件建议使用不同聊天。

分块上传与 HuggingFace 直传

原接口保留，上传步骤使用同样的上传认证。普通文件可直接使用 POST /upload。

分块上传流程
步骤POST 接口表单字段
初始化/upload?initChunked=trueoriginalFileName、originalFileType、totalChunks。
上传每块/upload?chunked=truefile、chunkIndex（从 0 开始）、uploadId、totalChunks、originalFileName、originalFileType。
合并/upload?chunked=true&merge=trueuploadId、totalChunks、originalFileName、originalFileType。
取消并清理分块/upload?cleanup=true&uploadId={ID}&totalChunks={数量}无需文件。

初始化响应返回 uploadId。初始化时传入 expiresIn 或 permanent=true 固定保存策略，合并时不能改为其他值，永久合并会再次验证权限。文件有效期从合并完成时开始，合并响应仍为含 src、expiresAt 的数组。分块上传会话有效期为 1 小时，独立于文件有效期。WebDAV 不支持分块上传。

HuggingFace 直传流程
  1. POST /upload/huggingface/getUploadUrl：JSON 请求传 fileSize、fileName、sha256、fileSample 等字段，获取上传信息。
  2. 按返回的上传信息向存储服务发送文件；多段上传按返回的完成地址提交，本站代理接口为 POST /upload/huggingface/completeMultipart。
  3. POST /upload/huggingface/commitUpload?expiresIn=86400：提交 JSON，必需字段 fullId、filePath、sha256、fileSize；可附 fileName、fileType、channelName。

保存参数在 commitUpload 的查询字符串中指定，规则与普通上传相同。响应是对象，包含 success、src、expiresAt、fileUrl、fullId，配置公开前缀时还包含 publicUrl。需要受本站有效期控制时使用 src；fileUrl 是存储服务直链。

旧接口兼容

  • 上传路径仍为 POST /upload，文件字段仍为 file，原鉴权方式和渠道参数保留。
  • 普通上传仍返回数组，原 src 及条件性 publicUrl 保留，新增 expiresAt。读取 response[0].src 的旧脚本可继续使用；严格校验响应字段的客户端需允许新增字段。
  • 保存行为有变化：不传保存参数的新上传默认 24 小时，到期后链接返回 404。依赖永久链接的调用需显式传 permanent=true 并使用对应管理员凭据。
  • 已有旧文件缺少到期字段，继续按永久文件处理，不批量迁移。没有一次性模式，也没有按 Token 单独设置文件时长的配置。
  • sessionCheck 新增保存策略字段；过期清理接口是新增接口，原接口没有删除或改名。
